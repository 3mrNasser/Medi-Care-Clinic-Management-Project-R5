# 6. Testing & Quality Assurance

**Project:** MediCare – Clinic Management & Appointment System (DEPI · Full Stack .NET)  
**Scope:** test plan, test cases and expected results, automated tests, and the bug report with resolutions.

---

## 6.1 Test plan

### Objectives
- Every functional requirement works for its role (Patient, Doctor, Admin) and is blocked for the others.
- Booking rules hold under all conditions: no double booking, working hours, days off, past times.
- Notifications reach the right person through the right channel.
- Sensitive data (medical records, documents) is visible only to the patient and their doctors.
- The UI works on desktop and mobile, in light and dark mode, with no broken links.

### Test levels and tools
| Level | What | Tool | Where |
| :--- | :--- | :--- | :--- |
| **Unit** | Notification Factory, Appointment Factory, reminder rules | xUnit | `MediCare.Tests/NotificationFactoryTests.cs`, `AppointmentFactoryTests.cs` |
| **UI (automated)** | Critical paths through the real pages and forms: login per role, access rules, booking, confirmation + notification, admin report | xUnit + `Microsoft.AspNetCore.Mvc.Testing` (in-memory app, SQLite) | `MediCare.Tests/UI/CriticalPathUiTests.cs` |
| **Integration** | Services + Generic Repository + Unit of Work on a real (in-memory SQLite) database | xUnit, EF Core SQLite | `MediCare.Tests/AppointmentServiceTests.cs`, `ClinicServicesTests.cs` |
| **End-to-end (HTTP)** | Full flows against the running site with the dev accounts (login, anti-forgery tokens, redirects, roles) | PowerShell scripts | run before each pull request |
| **UI / visual** | Pages in a real browser (Edge), light/dark, desktop/mobile, live notifications | Browser + Playwright screenshots | `docs/screenshots/` |
| **Link crawl** | Every link on every page for anonymous, patient, doctor and admin | PowerShell crawler | run before each pull request |
| **Continuous integration** | Build + all automated tests on every pull request and push to `main` | GitHub Actions | `.github/workflows/ci.yml` |

### Environment
- .NET 10 SDK, SQL Server LocalDB (`MediCareDb`), Development environment (seeded doctors, slots and dev accounts).
- Browsers: Microsoft Edge (Chromium) desktop 1366×768 and mobile 375–390 px.
- CI: `ubuntu-latest`, .NET 10, Release build.

### Entry / exit criteria
- **Entry:** the solution builds without errors and the database is migrated.
- **Exit:** 100% of automated tests pass, all end-to-end checks pass, the link crawl finds 0 broken links, and no errors
  appear in the server log.

## 6.4 Bug report

Bugs found during development and testing, with their fix.

| ID | Bug | Severity | How it was found | Root cause | Fix | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| BUG-01 | Each appointment appeared twice on *My Appointments* (once in Upcoming, once in History) | High | Manual test with real data | `Except()` ran twice on a deferred LINQ query | Materialize the list with `ToList()` before splitting | ✅ Fixed |
| BUG-02 | Doctor role lost after a failed sign-up (fell back to Patient) | Medium | Reported by the Identity developer | View read the role only from the URL | View reads `Model.Role` first, then the posted value, then the URL | ✅ Fixed (PR #7) |
| BUG-03 | After login, a later user was sent to an old page | High | End-to-end test (admin landed on `/DoctorAppointments`) | `returnUrl` kept in TempData from an abandoned login | Removed TempData; the form posts `ReturnUrl` (local only) | ✅ Fixed (PR #12) |
| BUG-04 | Access-denied page returned plain text | Low | Manual test | `Content(...)` instead of a view | Designed 403 page with role-aware buttons | ✅ Fixed (PR #10) |
| BUG-05 | Printed prescription had a grey block under the content | Low | Print preview | Full-height layout + background in print | Print CSS: white page, no full-height layout | ✅ Fixed |
| BUG-06 | Calendar toolbar buttons used the wrong colors | Low | Visual check | FullCalendar default theme | FullCalendar CSS variables set to the brand colors | ✅ Fixed |
| BUG-07 | Charts kept dark-mode colors after switching to light mode | Low | Visual check | Charts drawn once with the colors at load time | Charts redraw on the `vt-theme-change` event | ✅ Fixed |
| BUG-08 | Doctor saw "added by You" on a file uploaded by the patient | Low | Visual check | Label compared uploader with patient, not with the viewer | Label based on the viewer ("you", "the patient", doctor name) | ✅ Fixed |
| BUG-09 | Static files came back empty when running the build output in Production | Medium | Local Production run | `MapStaticAssets` manifest only matches a published app | Documented: use `dotnet publish` (CI deploy does) or Development | ✅ Documented |
| BUG-10 | Build warning: known high-severity vulnerability in `SQLitePCLRaw.lib.e_sqlite3` 2.1.11 (tests only) | Medium | Release build | Transitive dependency of EF Core SQLite | Pinned 2.1.14 in the test project | ✅ Fixed |
| BUG-11 | Pages linked to removed features (AI Assistant, Pharmacy, Labs…) | Medium | Scope change | Features removed from scope | Pages, links, styles and images removed; crawler confirms 0 broken links | ✅ Fixed (PR #13) |
